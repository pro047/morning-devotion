# PRD: F-1 M4 다음 묵상 화면

작성일: 2026-11-20 · 상위 PRD: [f-1-next-devotion.md](f-1-next-devotion.md) · 이전 마일스톤: [f-1-m3-video.md](f-1-m3-video.md)

F-1 을 4개 마일스톤으로 나눈 것 중 **M4** 다. 이 문서가 이번 범위의 정본이고, F-1 PRD 는 배경으로만 읽는다.

## 1. 범위
M1~M3 로직을 앱 화면에 잇는다. 1) 앱을 열면 진행 위치로 **다음 묵상의 목록을 가져와** 고르고, 2) 글과 영상을 한 화면에 보여주고, 3) "다 봤어요" 뒤에는 그 시간대의 완료 화면을 보여주고, 4) 실패하면 안내 문구를 보여준다. YouTube API 키를 앱 설정에서 읽는 연결도 한다.

대응하는 F-1 요구: FR-2·FR-6·FR-8, US-1 수용 기준 3, US-2 수용 기준 3·4, US-3 전체, US-5 전체, 9장 1번 결정(A안, 2026-11-20).

## 2. 요구사항
- R-1: 다음 묵상의 **목록 HTML 을 날짜 검색으로 가져온다** (M1 은 목록 HTML 을 입력으로 받기만 하고, 목록 주소는 아직 어디서도 만들지 않는다 — 코드 확인 `DevotionArticleURL.swift` 는 글 주소만)
  - 주소: `https://100church.org/home/board.php?board=cast&config=6&category=6&search=<yyyy/MM/dd>&shwhere=subject`
  - 마지막으로 본 날짜 + 1일부터 하루씩 검색해, 결과가 있는 첫 날짜의 목록을 M1 `NextDevotionPicker` 에 넣는다. **최대 7일**까지 (2026-11-20 진성 결정, 7장 1번)
  - 실측(2026-11-20, 5장): `2025/09/12` → 1건, `2025/09/14`(일) → 0건, `2020/07/14` → 1건
  - 가져오기는 M2 의 `DevotionHTMLFetching` 프로토콜을 그대로 쓴다. 테스트는 가짜 구현으로 fixture 를 돌려준다 — 테스트는 네트워크를 쓰지 않는다
- R-2: 화면 상태를 정하는 로직은 SwiftUI 뷰와 분리해 단위 테스트한다. 현재 시각(Date·Calendar)·저장소·가져오기·검색은 모두 주입한다
  - 상태: 불러오는 중 / 묵상 표시 / 오늘 마침 / 인터넷 오류 / 다음 묵상 없음
- R-3 (US-1 기준 3): 묵상 표시 화면 = 위에 영상, 아래에 날짜·본문·찬송·설교문(M2 `DevotionArticleParser` 결과, 글자만), 맨 아래 "다 봤어요" 버튼
- R-4 (US-2 기준 3·4): 영상
  - M3 결과가 `found` → 그 영상을 앱 안에서 재생한다 (유튜브 앱으로 넘기지 않음). 재생 방식은 설계 단계에서 정한다
  - `notFound` → 영상 자리에 "영상을 찾지 못했습니다". 글은 그대로 보이고 "다 봤어요"도 누를 수 있다
  - `searchFailed` → 영상 자리에만 "인터넷 연결을 확인해 주세요". 화면 전체를 오류로 바꾸지 않는다 — 글은 그대로, "다 봤어요"도 누를 수 있다 (2026-11-20 진성 결정, 7장 2번)
  - API 키가 없거나 빈 문자열 → 검색을 부르지 않고 영상 자리에 "영상을 찾지 못했습니다"
- R-5 (9장 1번 A안): "다 봤어요"
  - M2 `markSeen` 으로 그 구분의 진행 위치를 화면의 묵상 날짜로 바꾸고, **그 구분을 마친 날(기기 로컬 날짜)** 을 함께 저장한다 — 저장 키가 구분마다 하나씩 늘어난다 (키 이름·형식은 설계 단계, 기존 키 `readingProgress.lastSeenOld/New` 는 바꾸지 않는다)
  - 누른 뒤 화면: "오늘 구약 묵상을 마쳤습니다" (신약은 "오늘 신약 묵상을 마쳤습니다")
- R-6: 앱을 열 때(그리고 "다시 시도" 때) 현재 구분의 마친 날이 **오늘(기기 로컬 날짜)** 이면 "오늘 마침" 상태로 끝낸다. 홈페이지·유튜브를 부르지 않는다
  - 날짜가 바뀌는 기준은 00:00 이다. 23:50 에 신약을 마치고 00:10 에 열면 구약 다음 묵상이 나온다 (2026-11-20 진성 승인)
- R-7 (US-5, FR-8): 안내 문구
  - 목록·글 가져오기가 네트워크 오류 → "인터넷 연결을 확인해 주세요" + "다시 시도" 버튼
  - R-1 에서 7일 안에 결과가 없음 → "다음 묵상을 찾지 못했습니다"
  - 두 경우 모두 진행 위치·마친 날은 바뀌지 않는다
- R-8: API 키 연결 — `Secrets.xcconfig` 의 `YOUTUBE_API_KEY` 를 빌드 설정 → Info.plist 로 넘겨, 앱이 실행 중에 읽는다
  - 지금 프로젝트는 `GENERATE_INFOPLIST_FILE=YES` 이고 xcconfig 가 연결돼 있지 않다 (코드 확인 `MorningDevotion.xcodeproj/project.xcproj:42`, `xcconfig` grep 0건). 사용자 정의 키를 생성 Info.plist 에 넣는 방법은 설계 단계에서 확인한다 (미확인)
  - 키는 git 에 커밋하지 않는다. `Secrets.xcconfig` 는 `.gitignore` 에 있다 (실측). 커밋되는 것은 `Secrets.example.xcconfig` 뿐
  - Info.plist 값을 읽는 부분은 딕셔너리를 받는 함수로 둔다 (테스트용)

## 5. 실측 메모 (2026-11-20)
- 날짜 검색 3회 모두 HTTP 200. `shwhere=subject` 라 제목만 찾으므로 F-1 PRD 7장의 "본문(`tbody`)까지 찾아 관계없는 글이 섞이는" 문제가 없다

- 날짜 검색은 앱을 열 때마다 최소 1회, 빈 날마다 1회씩 더 든다. 홈페이지 요청이라 YouTube 할당량과는 무관

## 6. 하지 않는 것
- 시간대와 다른 구분으로 바꿔 보는 버튼 (F-1 PRD 9장 2번): 만들지 않음. 점심 묵상을 놓친 날은 다음 날 점심까지 신약을 볼 수 없다
- 같은 본문의 다른 해 영상으로 대신 보여주기 (9장 5번): 하지 않음. "영상을 찾지 못했습니다"로 끝낸다
- 임베드가 거부된 영상을 유튜브 앱으로 넘기기 (9장 3번): 하지 않음. 실측 영상 4개 모두 `embeddable=true`(M3 5장). 수동 확인에서 거부가 나오면 그때 다룬다
- 설교문 굵은 글씨(소제목·성경 구절) 구분: 하지 않음. M2 파서가 글자만 남기므로 넣으려면 M2 파서를 고쳐야 한다
- 영상 id·글 캐시, 지난 묵상 목록(F-2), 처음 진행 위치 입력 화면(9장 4번 결정)
- 화면 UI 테스트(XCUITest), 실제 네트워크 요청 테스트
