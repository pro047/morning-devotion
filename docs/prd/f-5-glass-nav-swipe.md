# PRD: F-5 이전·다음 글래스 화살표와 스와이프

작성일: 2026-11-22 · 프로젝트 PRD: [00-project.md](00-project.md) · 관련: [f-4-prev-next.md](f-4-prev-next.md)

## 1. 개요
F-4로 메인 줄과 묵상 화면에 "이전"·"다음"이 생겼다. 지금은 글자 버튼이다 (메인: 카드 안 `.bordered` 버튼 두 개, 묵상 화면: 하단 툴바 글자 버튼). 진성은 "좀 더 이쁜 버튼"을 원했고, 원형 글래스 화살표(A안)에 스와이프를 더하기로 했다 (2026-11-22).
이 기능은 F-4의 이동 동작(무엇을 찾고, 진행 위치를 바꾸지 않는 것)은 그대로 두고
1. 버튼을 앱의 Liquid Glass 스타일에 맞는 원형 화살표로 바꾸고
2. 같은 이동을 좌우 스와이프로도 할 수 있게 하고
3. 넘어갈 때 옆으로 밀려나는 전환과 가벼운 햅틱을 준다
4. 메인 줄에 "다음 묵상을 찾지 못했습니다"가 뜬 경우에도 "이전"으로 갈 수 있게 한다 (F-4 Attention #26)

## 2. 목표
- 메인 카드와 묵상 화면의 이전·다음이 글자 대신 원형 글래스 화살표로 보인다
- 버튼을 누르지 않고 좌우로 밀어도 같은 글로 넘어간다
- 메인 줄에 다음 글이 없어도 앞 글로 넘겨 볼 수 있다

## 3. 사용자 스토리

### US-1: 메인 카드의 원형 화살표
**설명:** 진성으로서, 메인 카드에서 이전·다음을 앱 디자인에 맞는 화살표로 누르고 싶다. 지금 글자 버튼이 밋밋하기 때문이다.
**수용 기준:**
- [ ] 글이 보이는 메인 줄에는 본문 제목 왼쪽에 `‹`, 오른쪽에 `›` 원형 글래스 버튼이 있고, "이전"·"다음" 글자 버튼은 없다
- [ ] `‹` 를 누르면 F-4 메인 줄 "이전"과 같은 결과가 나온다 (그 줄만 앞 글로 바뀌고 묵상 화면은 열리지 않는다)
- [ ] `›` 를 누르면 F-4 메인 줄 "다음"과 같은 결과가 나온다
- [ ] 이동 검색 중에는 두 화살표가 잠기고 불러오는 중 표시가 보인다
- [ ] 화살표 밖의 카드를 누르면 지금처럼 그 줄의 묵상 화면이 열린다

### US-2: 묵상 화면의 떠 있는 화살표 캡슐
**설명:** 진성으로서, 묵상 화면 아래쪽에 떠 있는 화살표로 앞뒤 글로 넘어가고 싶다.
**수용 기준:**
- [ ] 묵상 화면 하단 가운데에 `‹`·`›` 를 담은 글래스 캡슐이 떠 있고, 하단 툴바의 "이전"·"다음" 글자 버튼은 없다
- [ ] 캡슐의 `‹`·`›` 는 F-4 묵상 화면 "이전"·"다음"과 같은 결과를 낸다
- [ ] 이동 검색 중에는 캡슐 가운데에 불러오는 중 표시가 보이고 두 화살표가 잠긴다
- [ ] 캡슐이 "다 봤어요" 버튼과 겹쳐 둘 중 하나를 누를 수 없게 되지 않는다

### US-3: 좌우 스와이프로 넘기기
**설명:** 진성으로서, 버튼을 찾지 않고 좌우로 밀어서 넘기고 싶다. 책장을 넘기듯 읽고 싶기 때문이다.
**수용 기준:**
- [ ] 메인 카드를 왼쪽으로 밀면 그 줄의 `›`(다음)와, 오른쪽으로 밀면 `‹`(이전)와 같은 결과가 나온다
- [ ] 묵상 화면의 글을 왼쪽으로 밀면 다음 글, 오른쪽으로 밀면 이전 글로 넘어간다
- [ ] 위아래 스크롤로 글을 읽는 동안에는 넘어가지 않는다 (가로로 충분히 민 경우에만 넘어간다)
- [ ] 이동 검색 중에 다시 밀어도 이동이 겹쳐 일어나지 않는다
- [ ] 메인 구약 카드를 밀어도 신약 줄은 바뀌지 않는다

### US-4: 전환과 햅틱
**설명:** 진성으로서, 넘어갈 때 어느 쪽으로 갔는지 눈과 손으로 알고 싶다.
**수용 기준:**
- [ ] 다음 글로 가면 새 글이 오른쪽에서, 이전 글로 가면 왼쪽에서 들어온다 (메인 줄 내용과 묵상 화면 모두)
- [ ] 새 글을 찾을 때까지는 지금 글이 그대로 있고 불러오는 중 표시가 보인다. 찾은 뒤에 전환한다
- [ ] 넘어가는 데 성공하면 가벼운 햅틱이, 더 갈 글이 없거나 네트워크 오류면 그와 다른 햅틱이 한 번 울린다

### US-5: 다음 글이 없는 메인 줄에서 이전으로 가기
**설명:** 진성으로서, 메인 줄에 "다음 묵상을 찾지 못했습니다"가 떠도 앞 글로 넘겨 볼 수 있으면 좋겠다.
**수용 기준:**
- [ ] 메인 줄이 "다음 묵상을 찾지 못했습니다"일 때 그 줄에 `‹` 가 있고 `›` 는 없다
- [ ] 그 `‹` 를 누르거나 카드를 오른쪽으로 밀면 그 구분의 진행 위치 날짜 글이 "읽음" 표시와 함께 줄에 보인다
- [ ] 그 상태에서 다시 `‹` 는 F-4 "이전"과 같이 동작한다
- [ ] 진행 위치 날짜 글을 못 찾거나 네트워크 오류면 줄은 "다음 묵상을 찾지 못했습니다" 그대로이고 F-4 US-5의 문구가 보인다
- [ ] 이 과정에서 진행 위치는 바뀌지 않는다

## 4. 기능 요구사항
- FR-1: 이전·다음 화살표와 스와이프는 F-4의 이동(찾는 범위, 진행 위치 불변, 못 찾음·오류 문구)과 같은 동작을 불러야 한다. 이동 규칙을 새로 만들지 않는다
- FR-2: 메인 카드의 `‹`·`›` 는 원형 글래스 버튼이어야 하고, 누를 수 있는 영역은 가로·세로 44pt 이상이어야 한다
- FR-3: 묵상 화면의 `‹`·`›` 는 화면 하단 가운데에 떠 있는 글래스 캡슐 안에 있어야 한다
- FR-4: 사용자가 메인 카드나 묵상 화면 글을 가로로 밀면, 왼쪽은 다음·오른쪽은 이전으로 이동해야 한다
- FR-5: 세로 스크롤 중에는 이동하지 않아야 한다
- FR-6: 이동 검색 중에는 화살표와 스와이프가 새 이동을 시작하지 않아야 한다 (F-4 이동 중 잠금과 같은 조건)
- FR-7: 이동이 성공하면 이동 방향에 맞는 밀려나는 전환으로 내용을 바꿔야 한다
- FR-8: 이동 성공·실패 시 서로 다른 햅틱을 한 번씩 줘야 한다
- FR-9: 화살표 버튼에는 VoiceOver 라벨 "이전 묵상"·"다음 묵상"이 있어야 한다
- FR-10: 메인 줄이 "다음 묵상을 찾지 못했습니다"일 때는 `‹` 와 오른쪽 스와이프만 있어야 하고, 이것을 쓰면 그 구분의 진행 위치 날짜 글을 찾아 "읽음"으로 보여줘야 한다

## 5. 하지 않는 것
- 이동 규칙(찾는 범위 ±7일, 진행 위치 불변) 변경
- 앞뒤 글의 날짜를 미리 찾아 화살표 옆에 보여주기 (검색이 늘어난다)
- 한 손가락으로 끌어 가는 동안 다음 글이 따라 보이는 페이지 넘김(미리보기) — 새 글은 검색이 끝나야 생긴다
- 다른 화면의 버튼 디자인 변경

## 6. 화면·사용 흐름
- 메인 카드: `‹  2025/09/12(금) 잠언 24:1-10  ›` — 화살표는 원형 글래스, 제목은 가운데. "지금"·"읽음" 배지는 지금 자리
- 묵상 화면: 글은 지금 배치 그대로, 하단 가운데에 `‹ · ›` 글래스 캡슐이 떠 있다. 가운데 점은 이동 중 불러오는 중 표시로 바뀐다
- 재사용: `Theme.swift` 의 글래스 스타일(메인 카드·"다 봤어요"가 쓰는 `glassEffect`·`glassProminent`)

## 7. 기술적 고려
- 메인 카드 전체에 탭으로 묵상 화면을 여는 동작이 걸려 있다. 화살표·스와이프가 이 탭보다 먼저 처리돼야 한다 (F-4 체크리스트 D:411)
- 묵상 화면에서 화면 왼쪽 끝을 오른쪽으로 미는 동작은 iOS 뒤로 가기(메인으로)와 같다. 오른쪽 스와이프(이전)와 겹친다 — 9장
- 묵상 화면 위쪽 영상(`WKWebView`)은 자체 터치를 받는다. 영상 위에서의 스와이프는 9장
- 이동 검색은 목록 검색 1~7회라, 스와이프 직후 바로 넘어가지 않을 수 있다 (US-4 기준 2)
- 화면 모양·제스처·햅틱은 단위 테스트로 판정하기 어렵다. 판정할 수 있는 것은 "화살표·스와이프가 같은 이동을 부르는가", "이동 중 새 이동을 막는가", FR-10의 줄 상태다. 나머지는 실기기 확인
- F-4(`pipeline/f-4-prev-next`, 233fca8) 위에서 만든다. F-4 실물 확인은 이 기능을 설치한 뒤 함께 한다
