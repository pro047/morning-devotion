# PRD: F-1 M3 묵상 영상 찾기

작성일: 2026-11-20 · 상위 PRD: [f-1-next-devotion.md](f-1-next-devotion.md) · 이전 마일스톤: [f-1-m2-read-and-progress.md](f-1-m2-read-and-progress.md)

> **2026-11-23: R-1·R-2(검색어)·R-3(제목 형식)·R-5 는 [F-6](f-6-sermon-video.md) 이 대체한다** — 글 페이지 embed 가 2025 묶음에서 생방송(약 90분)이라 검색만 쓴다. 이 문서의 나머지는 배경으로 남긴다.

F-1 을 4개 마일스톤으로 나눈 것 중 **M3** 다. 이 문서가 이번 범위의 정본이고, F-1 PRD 는 배경으로만 읽는다.

## 1. 범위
묵상 하나에 맞는 **유튜브 영상 id** 를 정하는 로직. 1) 글 페이지 HTML 에서 영상 id 를 뽑고, 2) 글 페이지에 없으면 YouTube Data API 검색 결과에서 날짜·본문이 같은 영상을 고른다 (F-1 PRD FR-5, 2026-11-20 결정 C안).
화면·재생은 범위 밖이다. 로직과 단위 테스트만 만든다.

대응하는 F-1 요구: FR-5, US-2 의 수용 기준 1·2·4 (영상 id 를 정하는 부분만. 재생·안내 문구 표시는 M4).

## 2. 요구사항
- R-1: 글 HTML 에서 유튜브 영상 id 를 뽑는다. 두 형태를 모두 읽는다 (2026-11-20 실측, F-1 PRD 7장)
  - 2023~2025: `<iframe ... src="https://www.youtube.com/embed/<id>" ...>` — 예: `cast-body-15155.html` → `PR9GK_S83NU`
  - 2022: 본문 제목 링크 `<a href="https://www.youtube.com/embed/<id>">창세기 32:1-20 <img ...></a>` — 예: `cast-body-12602.html` → `UsCVP4y7snI`
  - 2020~2021: 영상 없음 — 예: `cast-body-11480.html` → 없음
  - id 글자: `A-Z a-z 0-9 _ -` (실측 id 에 `-rD7ZDYCysw`·`_2LlTBb4aDQ` 처럼 `-`·`_` 로 시작하는 것이 있다)
- R-2: 글 페이지에 영상이 없을 때만 YouTube Data API `search.list` 로 찾는다
  - 요청: `https://www.googleapis.com/youtube/v3/search` · `part=snippet` · `channelId=UCSkjujMSzrh6nghHWTSvIJg`(100주년기념교회, 핸들 `@100_CHURCH`) · `type=video` · `maxResults=5` · `q=<날짜> <본문>` (예: `2020/07/13 요한복음 5:30-47`) · `key=<API 키>`
  - 검색 요청은 M2 의 글 가져오기처럼 **프로토콜 뒤에 둔다.** 테스트는 가짜 구현으로 fixture JSON 을 돌려준다 — 테스트는 네트워크를 쓰지 않는다
  - API 키는 호출하는 쪽이 넘긴다. 키를 어디서 읽을지(`Secrets.xcconfig` → Info.plist 연결)는 M4. 키는 git 에 커밋하지 않는다
- R-3: 검색 결과(`items[].snippet.title`) 중 **날짜와 본문이 묵상과 같은 첫 영상**을 고른다. 없으면 "영상 없음"
  - 영상 제목 형식(2020): `2020/07/13(월) “요한복음 5:30-47” / 박성호` — 글 제목과 달리 `작성:` 이 없다. 이대로 M1 제목 파서에 넣으면 본문이 `요한복음 5:30-47 / 박성호` 가 된다 (코드 확인 `DevotionTitleParser.swift` authorPattern)
  - API 는 제목의 따옴표를 HTML 엔티티로 준다: `2020/04/14(화) &quot;누가복음 5:1-16&quot; / 박성호` (fixture 원문). 엔티티를 푼 뒤 비교한다
  - 같은 날짜의 다른 영상이 섞인다: `2020/04/29,  수요성경공부 민수기 1:1-54 …` — 날짜만 같고 본문이 다르면 고르지 않는다
  - 표기 차이(따옴표 `“` `"`, 구간 기호 `-` `~`)는 F-1 FR-7 대로 같은 것으로 본다
- R-4: 결과는 세 가지로 구분한다: 영상 id 찾음 / 영상 없음(글 페이지에도 없고 검색에서도 못 찾음) / 검색 실패(네트워크·HTTP 오류·응답 형식 깨짐). "영상 없음"과 "검색 실패"는 M4 에서 다른 처리를 할 수 있게 구분한다 (US-2 수용 기준 4, FR-8)
- R-5: 글 페이지에서 영상을 찾으면 검색을 **부르지 않는다** (할당량을 쓰지 않음)

## 5. 실측 메모 (2026-11-20)
- 2020 영상의 `publishedAt` 은 `2020-09-13T06:04:38Z` 로, 묵상 날짜(2020/07/13·14)와 다르다 — 일괄 업로드. **올린 날짜로 거르면 안 된다.** 제목의 날짜로 비교한다
- `videos.list` `status.embeddable`: `PR9GK_S83NU`·`g3DiBZ_iNnA`(2025 생방송, `unlisted`, 약 1시간 30분)·`UsCVP4y7snI`·`95rGTpXD7DU`(public, 약 22분) 모두 `true`
- 할당량: `search.list` 1회 100 단위, 기본 하루 10,000 단위 (Google 문서 `determine_quota_cost`. 문서 판본에 따라 "search.list 하루 100회" 별도 한도라는 서술도 있어 어느 쪽이든 **하루 약 100회**로 본다. 콘솔에서는 미확인)
  - 사용량: 검색은 글 페이지에 영상이 없는 묵상(지금은 신약 2020 묶음)에만 쓴다. 앱을 하루 10번 열어 매번 검색해도 10회 = 한도의 10%
- 2021/06 ~ 2022/01 사이 어디서 글 페이지 영상이 생겼는지는 미측정. R-1·R-2 순서라 경계를 몰라도 동작은 같다 (글 페이지에 없으면 검색)
